## 找到并使用一项能力

使用一项能力时，先确定它属于哪个模块、名称是否已经可见。例如，`String` 和 `println` 具有默认绑定；异步组合需要显式导入：

```carven run
import std::async using when_all;

async fn amount() -> i32 => 42;
async fn ready() -> bool => true;

async fn main() {
    let (count, available) = await when_all(amount(), ready());
    println(count, available);
}
```

`when_all` 是 `std::async` 中的内建操作。编译器推导结果元组的元素类型与合并后的失败集合，并检查组合操作接管输入操作的所有权。显式导入让名称在当前模块中可见。

模块归属和默认可见性是两个独立属性。同一个标准模块可以同时包含编译器提供的声明与源码导出。即使编译器提供的条目没有对应的 `core.cv` 源文件，它们仍属于 `std::core` 这个标准模块。

默认绑定和导入规则见[模块参考](/zh/reference/modules/)；查找 API 所属模块时，使用[标准 API 索引](/zh/reference/library/)。

## 区分公共接口、语义和原生实现

同一项能力可以同时使用以下三层：

| 层次                          | 职责                                                                                    |
| ----------------------------- | --------------------------------------------------------------------------------------- |
| Standard Craft（标准 Craft）  | 通过标准模块组织公共声明与可复用源码实现                                                |
| Built-ins（内建能力）         | 编译器负责其类型、访问、生命周期、失败和执行语义的类型与操作                            |
| Runtime Craft（运行时 Craft） | 生成的 C++ 使用的原生表示和操作，包括存储、格式化、失败结果的数据表示、测试与异步驱动器 |

`when_all` 的公共条目属于 `std::async`，组合规则由编译器检查，生成的 C++ 使用 Runtime Craft 支持来执行。JSON 解析则由标准源码算法调用普通操作，构造源码定义的 `Value`。两者都遵循 Carven 的访问、所有权、失败和执行规则。

`print` 可以按顺序接收类型不同的多个实参；`when_all` 将不同类型的操作结果组合为元组。编译器根据实参类型确定每次调用的结果与执行契约。源函数则使用已有语言操作表达算法。

Standard Craft 位于 `crafts/carven/std/`，需要原生支持的能力在自身包内提供实现。Runtime Craft 位于 `crafts/carven/runtime/`。构建编译器不依赖这些 Craft 的 C++ 头文件和库；构建生成的原生应用时，再加入所用能力需要的支持。

## 区分运行支持与执行阶段

**Runtime Craft** 是原生支持包的名称，**运行时执行**是普通程序调用的执行阶段。`const` 初始化器或静态测试要求在编译器进程中执行；普通调用即便实参已知，也仍在运行时执行。

静态执行和解释执行由语义执行器实现受支持的内建操作，并运行标准源码函数；生成的 C++ 提供相应的原生表示和操作。两者在支持的阶段内保留相同的值、求值顺序、访问、所有权和失败。

编译器侧执行和宿主操作的规则见[常量参考](/zh/reference/constants/)，解释执行的用法见[命令参考](/zh/reference/cli/)。

## 把异步工作接到宿主资源

调用 Carven 异步函数创建冷操作，await 或启动子任务后通过驱动器执行。原生执行使用 C++ 协程；驱动器在一个线程上处理任务恢复、提供方事件和定时器。

原生异步提供方返回 `AsyncOperation<Result, Failures...>`，提交成功结果、声明的失败或取消状态，再将恢复 Carven 执行所需的任务加入调度队列。在宿主直接启动的异步操作及其子任务完成前，宿主必须保留事件源与资源。

`cancel` 请求停止；`close` 等待子任务及提供方清理后，才释放子任务仍在使用的借用。等待全部结果、选择结果和超时等组合操作也先关闭子任务再交付结果。提供方仍使用回调状态时，必须在清理期间保持状态有效。

原生输入、定时器和网络操作把驱动器接到宿主资源。对应 API 见[输入](/zh/reference/io/)、[时间](/zh/reference/time/)和[网络](/zh/reference/net/)参考。

[C++ 生成与原生集成](/zh/features/cpp-generation/)说明生成头文件、提供方边界和构建输入如何把这些能力接到原生应用。

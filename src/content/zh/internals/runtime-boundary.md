## 生成的程序依靠什么运行

生成的 C++ 需要文本存储、向量、失败结果、打印及异步执行的具体实现，这些支持位于 `crafts/carven/runtime/`。标准模块结合编译器提供的声明、`crafts/carven/std/` 中受检查的 Carven 源码，以及访问宿主所需的原生支持。

例如，JSON 解析是源语言算法；读取套接字则需要原生提供方，也就是按 Carven 声明契约完成宿主操作的 C++ 代码。编译器检查源码如何使用该契约，自身构建不依赖提供方头文件或原生库。

| 层次       | 职责                                                                      |
| ---------- | ------------------------------------------------------------------------- |
| 编译器     | 检查源契约，执行受支持的静态工作，生成 C++                                |
| 语言运行时 | 实现原生值、格式化、结果载体、测试及协程驱动器                            |
| 标准模块   | 提供 core、UTF、SIMD、JSON、输入、时间、异步与网络的公开 API 和受检查算法 |
| 原生提供方 | 完成宿主操作，保持隐藏资源有效                                            |
| 原生构建   | 编译并链接选定的生成源码、原生支持及依赖                                  |

`Read<T>`、`Duration`、`Timeout`、UTF 错误和输入句柄都是通过普通模块查找获得的标准源码声明。受检查的文本构造、输入错误映射及公开等待也有源函数体，宿主访问使用模块内的 provided 操作。

## 区分拥有数据与视图

拥有的 `String` 或 `Vector<T>` 可以复制为独立存储；`str` 和切片是视图，复制后仍指向原数据。静态执行与运行时执行使用相同关系。完成的常量保留拥有类型，冻结视图则具有不可变的程序生命周期存储。

原生传参保留检查过的观察关系。纯快照值可以按值传递；包含拥有存储的 Read 输入保留对该存储的访问。Write 使用可变引用，Take 在交付所有权的同时改变源绑定的可用性。

语义执行器在预算内跟踪有类型值和生命周期，生成的 C++ 提供相应存储、求值顺序和清理。编译器宿主地址不会直接复制为目标常量的原始地址。

## 等待工作及其清理完成

调用源异步函数创建冷操作，await 或启动子任务后，通过驱动器执行。原生执行使用 C++ 协程，就绪延续、提供方事件和定时器都在一个线程上处理。

原生异步提供方返回 `AsyncOperation<Result, Failures...>`，先提交成功、声明失败或取消，再将恢复源执行的延续排队。原生宿主用 `drive_root(operation, &source)` 驱动导出的根操作，并在根及子任务完成前保留事件源和资源。

请求取消不代表回调已经停止使用状态。`close` 等待子任务及提供方清理后，才释放子任务的活动借用。汇合、选择和超时组合也先关闭子任务，再交付结果。不接受取消的工作可能推迟这段等待。

## 将输入、定时器和 TCP 接到宿主

`std::io` 提供有界冷标准输入读取和字节分帧，`std::time` 提供受检查的时长、单调时点、等待和超时组合。静态调用使用编译器进程资源，普通调用使用运行时进程资源。浏览器的输入流为空，外部原生提供方需要本地原生宿主。

使用 `std::net` 时，C++ 宿主创建 `Network`，把已连接套接字交给地址稳定的 `Connection`，再将具名视图提供给 Carven。挂起操作和清理完成前，宿主保留这些对象及隐藏状态。每条连接可以同时有一个读和一个写，Windows 消费者链接 `ws2_32`。

这套源 API 处理已有连接上的读写，建立连接、监听、名称解析和 TLS 由宿主或它的库提供。完整契约见[网络参考](/zh/reference/net/)。

## 通过声明边界连接 C++

| 形式          | 连接方式                                                 |
| ------------- | -------------------------------------------------------- |
| 头文件导入    | 提供有序 C++ include 及委托的原生名字查找                |
| `import(cpp)` | 声明由 C++ 提供方实现的 Carven 可调用函数                |
| `export(cpp)` | 在模块的 `carven::api` 命名空间生成 API 头文件和函数外观 |
| `#[cpp]`      | 在实现产物中放置手写 C++ 源码                            |

C++ 检查外部名称、重载、模板和转换。适配层管理隐藏引用、回调保留、同步及原生异常。需要恢复异常时，应在它逃出生成的 `noexcept` 边界前捕获。

## 构建完整原生应用

`carven compile` 生成接口和实现，原生构建还需要所需的提供方源码、头文件路径和库。Xmake 规则安排源码发现、生成、编译和链接，见[工具链参考](/zh/reference/toolchain/)。

生成程序使用 C++20，编译器构建另有 C++26 宿主要求。[流收集器](https://github.com/ryblust/carven/tree/main/examples/stream_collector) 包含完整的 C++ 宿主，它调用 Carven 并接收拥有报告；[互操作教程](/zh/learn/interop/) 从第三方库调用开始。

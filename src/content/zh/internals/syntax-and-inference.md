## 给每一种拼写确定的职责

Carven 区分语法结构与编译器解析的名字。选择标识符和阅读代码时，这个区别很实用：一个熟悉的拼写，不一定是全局保留关键字。

| 形式                                                               | 怎样确定它的职责                                                                                       |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| `fn`、`if`、`let`、`throw` 等[保留关键字](/zh/reference/keywords/) | 词法分析产生专门的 token；普通声明不能用它们命名                                                       |
| `self`、`&self`、`&&self`                                          | 类操作参数中的 `self` 必须是首个无类型接收者，并确定访问方式；普通绑定与自由函数参数可以使用同名标识符 |
| `cpp`                                                              | 在 `import(cpp)` 或 `export(cpp)` 中选择原生边界，在 `#[cpp]` 中选择不解析的 C++ 源码片段              |
| `ptr<T>`                                                           | 类型位置的解析器识别普通标识符 `ptr` 并要求指针类型形式；这种形式不经过普通类型名字查找                |
| `r`、`f`、`c`                                                      | 与相应字符串分隔符紧邻时成为字面量前缀；独立出现时是标识符                                             |
| `println`、`assert` 等[内建函数](/zh/reference/builtins/)          | 通过普通名字查找确定；用户声明可以遮蔽它们                                                             |
| `i32`、`String` 等内建类型名字                                     | 语义分析解析内建类型，并禁止模块声明重用这些名字                                                       |

当前语法明确把 `self` 称为**上下文关键字**。它在类操作参数中必须位于首位并省略类型；自由函数的有类型参数与局部绑定可以使用同名标识符。表中其他依赖上下文的形式，各有自己的解析或查找规则；有特定含义的名字并不都属于关键字。模块路径还有一条明确的例外：路径组成部分也可以使用保留关键字的拼写。

```carven
class Counter {
    value: i32,
    fn create(value: i32) -> Counter => { value: value };
    fn read(self) -> i32 => self.value;
}

let self = 4;
let cpp = Counter::create(self);
println(cpp.read()); // 4
```

接收者的类型由所在类确定，访问遵循已有的 Read、Write、Take 规则。没有接收者的操作属于类的关联操作，无需再写 `static` 修饰符。把特殊解释限定在相应结构中，其他位置的普通名字就能继续作为普通名字使用。

## 让上下文补全类型，同时限定推断范围

类型标注、赋值目标、参数、返回类型或字段可以提供预期类型。它可以确定无后缀数字字面量的类型、枚举 `.Case` 的所属类型，以及具名字段构造的类型。[类型参考](/zh/reference/types/)列出了允许提供上下文的位置与转换。

```carven
enum State { Ready, Busy }
let state: State = .Ready;
assert(state == .Ready);

let count: usize = 3;
let next = 1 + count;
println(next); // 4
```

这里直接出现的无后缀 `1` 采用右操作数的 `usize` 类型。这是在确定字面量的类型，不是在提升一个已经存在的 `i32` 值。如果先把 `1` 存进没有类型标注的变量，它就已经是 `i32`，后续使用不会反过来改变它的类型。括号可以向内部传递预期类型，但不属于这条相邻操作数规则中的直接字面量。

这个边界让推断保持局部。普通 Carven 值没有通用的数字提升、真假值转换或结构转换。上下文无法确定某种省略形式时，直接写明类型。原生 C++ 操作则继续遵循独立委托给 C++ 的转换规则。

## 把影响行为的选择写出来

类型上下文不会补上调用的访问标记，也不会插入闭包捕获。Write 实参重复 `&`，Take 实参重复 `&&`。返回具名 owner 表达复制，必须满足相应的复制构造要求；转移则需要 `return &&owner;`。复制视图保留原来的底层关系，不会延长被引用对象的生命周期。

有些行为由结构的统一规则确定，无需每次额外加标记。普通调用先求值被调用者，再从左到右把运行时实参各求值一次。Write 允许别名，并不表示独占借用。Read 实参的表示保留原有存储时，可能观察到其他别名造成的修改；显式创建拥有副本则建立独立的直接值，但其中的视图与 Write 捕获仍引用原来的底层存储。[所有权参考](/zh/reference/ownership/)进一步说明存储与生命周期的影响。

失败处理中，`?` 选择传播，`try` 建立恢复边界。恢复保留已经完成的修改与外部副作用，不会自动形成事务；回滚属于应用算法。失败契约告诉调用者恢复之后还可能剩下什么失败。

## 区分执行许可与执行阶段

`const fn` 允许在必需静态上下文中执行，不会把每次调用都移到编译期。`const` 参数固定一个用于特化的输入，剩余函数仍可以在运行时执行。`let` 本身不要求编译期执行，阶段由外围执行上下文确定。运行时的 `let` 即使用字面量初始化，也不能为静态参数提供所需常量；在 `const` 块或 `const test` 中，局部绑定随代码块在编译期执行。

`const if` 选择生成的分支，但每个源码分支仍接受名字、类型、访问、所有权与失败契约检查。它在一份源码契约下完成特化，不提供隐藏非法代码的入口。[编译期文章](/zh/features/compile-time/)展示构造模型，[函数参考](/zh/reference/functions/)规定阶段选择规则。

## 从已有机制继续构建

三个具体方向符合现有分工，无需新增语法：

- 在普通 Crafts 中把已有 UTF 与 SIMD API 组合成扫描算法。算法由库选择；内建操作保留自己的 通道、内存与执行阶段契约。
- 用 `const fn`、常量初始化或 `const` 块等静态执行入口，以及允许的构造和冻结规则生成有界表格或文本。资源限制与静态结果约束仍属于契约。
- 把原生恢复策略放在 C++ 适配层，再通过显式边界暴露选定的结果。适配层在会终止程序的边界之前捕获原生异常，并明确外部对象的生命周期要求。

进一步扩展语言，需要一个现有形式不能充分表达的具体用途。先确定上下文来自哪里，访问或生命周期的变化怎样被看见，以及静态执行如何与原生执行一致。一个合法小例子、一个相邻的非法例子，以及对应的生成实现，可以让选择得到验证。这延续了 Carven 的[设计原则](https://github.com/ryblust/carven/blob/main/docs/development/principles.md)：源码写出重要约定，推断得出规则允许的事实，后续阶段负责落实。

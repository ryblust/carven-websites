## 从源码到原生程序

生成一次调用前，编译器需要知道实参类型、可能的失败，以及哪些存储必须保持有效。这些事实决定如何传值、失败出口通向哪里、需要清理什么。Carven 先确定这些问题，再构造 C++ 实现。

  <ol class="architecture-pipeline">

    <li><span>03</span><strong>检查与发布语义</strong><code>SemIRProgram</code></li>

  </ol>

</figure>

驱动将项目文件和标准库源码收集成一个源码批次，导入在该批次内解析。解析建立语法树，语义分析确定声明和表达式的含义并检查契约。后端再根据检查结果生成 C++，原生工具链检查委托的 C++ 操作，并编译、链接和优化程序。

## 同一条检查主线，几种命令出口

这些命令的区别在于检查完成后做什么：

| 命令               | 源码检查后的工作                             |
| ------------------ | -------------------------------------------- |
| `carven check`     | 完成分析、所需常量执行和静态测试后结束       |
| `carven interpret` | 通过解释器执行已检查操作                     |
| `carven compile`   | 规划并输出 C++ 产物                          |
| `carven main.cv`   | 生成 C++，与所需原生源码一起构建，再运行程序 |

共享分析使这些命令遵守相同的源规则，也让 `check` 能够在不调用 C++ 编译器的情况下执行静态测试。解释执行仍需要支持实际到达的操作，外部 C++ 实现需要原生执行。

## 展开看三个关键交接

<details class="architecture-detail">
<summary>语法树 → 语义程序：先确定源契约</summary>

`ProgramDraft` 是完成声明和函数体的可变状态。它先预留身份，再完成函数体，因此支持前向引用和递归。随后求解类型与失败集合，检查完整函数体、异步使用、所有权和局部指针可空性。

成功分析会发布 `SemIRProgram`：由确定类型、结构化操作、存储关系和源码来源组成的不可变程序。这里的“发布”表示这些事实通过了所需检查，可以交给其他阶段使用。错误阻止交接，警告可以随成功结果返回。

函数体完成后，分析还会确定哪些调用和 await 可能以取消完成。模板及完成的静态测试可以保留声明和源码来源，不保留运行时函数体。后端读取发布的程序，不再查询源语法树。

</details>

<details class="architecture-detail">
<summary>已检查操作 → 执行：在选定阶段运行</summary>

常量初始化器、`const` 块、静态测试和解释执行共享一套处理有类型值、控制流和存储的执行器。执行器应用资源预算，并根据执行中的实际值检查索引等操作。

显式编译期执行调用通过能力检查的 `const fn`。完成的常量保留类型，包括拥有的字符串、向量及嵌套 JSON 值；保留的视图具有不可变的程序生命周期存储。源异步组合及受支持的输入、时钟和等待使用选定执行宿主。

共享执行器使操作规则一致，各入口仍有自己的能力检查。解释运行请求不能让不支持的原生调用变得可执行；运行时结果已知，也不会让表达式自动成为合法的常量初始化器。

</details>

<details class="architecture-detail">
<summary>语义程序 → C++：规划实现，再写出文本</summary>

`PlannedCompilation` 借用不可变语义程序，并拥有 `TargetPlan`。计划选择名称、接口分组、结果表示和产物位置。规划和降低使用程序期间，程序保持存活且不可移动。

`BodyPreparation` 读取检查过的函数体事实，确定操作数对存储的需求。`BodyRealizer` 构造目标语句和表达式，安排求值、临时值、失败出口及清理。例如，后一个字段初始化失败时，前一个已完成字段仍需要正确的析构路径。

完成的 `TargetUnit` 接受验证，并收集头文件、原生导入和产物依赖。之后 emission 才将结构序列化为 C++ 文本，文件写出和原生工具链调用发生在更后面。

</details>

## 区分源规则与实现选择

| 源程序行为               | 生成必须保留什么                         |
| ------------------------ | ---------------------------------------- |
| 处理分支恢复一种失败     | 为调用者保留其他失败类型及其载荷         |
| 值借用了所有者的存储     | 在每次必要使用和清理前保持存储有效       |
| 静态分支或循环特化函数   | 生成选定工作，为展开迭代建立不同的局部值 |
| 表达式既有已知值又有效果 | 即使值不需要运行时计算，也保留效果       |
| 隐式操作未通过检查       | 保留让诊断能够解释问题的源码来源         |

语义分析确定什么有效，后端准备与实现阶段选择保留这些行为的实现。运行时支持提供原生操作，C++ 工具链完成其余原生检查和优化。

## 标准定义、产物与工作区查询

构建系统需要可复用的分析结果，编辑器需要当前源码的信息。两者使用同一条分析主线。

标准库分析可以在可执行程序之外保留泛型及分阶段函数的 `CheckedDefinitions`，消费者使用这些定义构造自己的实例。`compiler.artifact` 封装程序、可选定义、模块归属及是否可缓存。多个生成请求可以复用同一已检查程序，无需重复编译期工作。

工作区管理文档版本、解析快照、导航索引和有界分析缓存。每个未缓存选择都运行完整语义检查。错误后的查询可以保留已知源码信息，但不代表程序有效。到达输入、时钟读取或等待时，工作区给出诊断，避免编辑器分析执行这些宿主效果。

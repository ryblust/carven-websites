## 头文件和外部名字

```carven
import <vector> using std::vector;
import "provider.hpp" using vendor::{ Widget, create };
import <cstdio> using std::printf;
```

Carven 不解析头文件。没有 using 的导入不创建 Carven 名字。前导 `::` 直接选择 C++ 全局名字，可用于表达式、类型、cast 和构造；Carven 不要求必须先导入头文件，C++ 检查声明实际可见性。

显式 using 将末尾分量绑定到完整外部路径；重复同路径允许，同名不同路径是错误。显式选择优先于 namespace wildcard，所有等价显式来源一起标记使用。同一路径的重载由 C++ 处理，没有跨路径重载合并。列表项只能是简单标识符，不支持别名、嵌套列表或列表内 wildcard。

局部与模块声明保留普通查找。外部导入不能撞本地模块声明。未解析名字才使用打开的 C++ namespace。外部名字只在当前模块生效，不通过 Carven 模块导入再导出。显式选择有未使用诊断，namespace wildcard 没有。

## 类型、构造与转换

外部类型参数只能是类型，可嵌套；不支持 Carven 用户泛型。`T { ... }` 对原生类型使用位置初始化，可以为空。函数签名和字段中的原生类型必须显式命名，局部 owner 可从原生表达式推断。

当目标与值类型不同且至少一方为原生类型时，普通初始化、赋值、Read/Take 实参、返回、聚合和有类型的值分支委托 C++ 构造目标类型，包括窄化约束。Write 参数保持源存储，通过 C++ 检查是否能绑定引用；仍需 `&` 和可写检查。显式 `as` 在任一方为原生类型时生成 `static_cast<T>`。

原生条件转 bool；`&&/||` 保留 Carven 短路。原生一元与非逻辑二元操作的重载和结果类型由 C++ 检查。推断为外部表达式类型后，即使 C++ 最终认为它是 int，Carven 也不自动认定等价于 i32。

原生构造可用性不在 Carven 分析中证明。早期聚合组件若跨后续失败被保存，最终构造可能需要复制或移动；不能复制/移动的组件可能在 C++ 阶段失败。可直接最终位置构造的 prvalue 不因此全部被禁止。

例如，聚合第一个成员来自原生工厂，第二个成员的求值可能失败：编译器先完成并保存第一个成员，再求值第二个。全部成功后，保存值才进入最终聚合。原生类型若删除了所需复制和移动构造，最后一步无法成立；工厂能够直接返回不可移动值，并不足以保证这个聚合写法可用。需要在原生适配器中完成相应整体构造，或让成员类型支持实际发生的传递。

## C 字符串

`c"text"` 产生指向静态不可变、尾随 NUL 存储的外部 `const char*`。空字符串可用，内部 NUL 和 `\0` 非法。即使直接传给模板，也是指针而非字符数组。它不是 str，不参加 Carven 常量或字面量模式；保持外部类型并应用原生转换。

## 访问与生命周期

未标记实参 Read，`&` 为 Write，`&&` 为 Take。接收者继承存储访问。原生引用返回值初始化局部绑定时仍建立拥有值，受 C++ 构造约束。原生成员与索引继承根访问；原生索引采用提供者边界行为。

Carven 检查已知 owner 可用性、显式冲突和已知文本 backing。它不推断 C++ 引用保留、指针存活或迭代器失效。已知 callable 借用和 Write 捕获不能穿过未声明外部契约。原生引用绑定、指针算术和外部迭代协议不支持。

直接 C++ 调用可接收动态文本视图和包含它们的聚合，保护已知 backing 到实参和调用结束。提供者与调用者负责长期保留、返回别名、重入和间接指针寿命。Write 视图槽位不证明其解除旧 backing 借用。

原生调用、构造和表示转换的返回值不建立新的已知借用关系，即使返回 Carven 类型。String 不隐式变成原生字符串容器。

## `#[cpp]`

每个顶层片段原样进入实现文件，保持独立，不解析或插入 Carven 值，不绑定同名 Carven 声明。宏、重载、模板、链接、异常、对象生命周期、ODR 和原生未定义行为由 C++ 契约负责。

## 显式 scalar 边界

```carven
private import(cpp) fn native_value(value: i32) -> i32;

export(cpp) fn answer() -> i32 => 42;
```

import(cpp) 是 private 或裸无体声明，调用同名无前缀全局 C++ 函数。Carven 不生成提供者声明、不解析比较其签名；定义、匹配和链接由作者/工具链完成。不同模块的同名导入仍是不同 Carven 能力。

export(cpp) 是有体且对全批次可见的 Carven 函数，同时进入生成 API。不能直接导出 import(cpp)，需要普通包装函数。两方向均要求固定参数个数、无失败、Read 按值参数的顶层函数；不支持 Write/Take 或非空失败集合。

| Carven         | C++                                     |
| -------------- | --------------------------------------- |
| bool           | bool                                    |
| i8/i16/i32/i64 | std::int8_t/int16_t/int32_t/int64_t     |
| u8/u16/u32/u64 | std::uint8_t/uint16_t/uint32_t/uint64_t |
| isize/usize    | std::ptrdiff_t/std::size_t              |
| f32/f64        | float/double                            |
| char           | char32_t，入站检查标量有效性            |
| void           | 仅结果                                  |

str、String、数组、结构体、枚举、指针、callable、入口参数和范围视图不在此 scalar 边界内。头文件直接调用的原生能力与此闭合接口是不同形式。

提供者名不能是 main/std/carven。前导下划线的 C++ 保留规则由作者负责。export API 中安全名字保持拼写；不安全名字或以 `cv_escaped_` 开头的名字用该前缀加原 UTF-8 字节小写十六进制编码。排除 C++ 关键字、双下划线和 `_` 加大写首字母。函数/namespace 前缀冲突非法。

## noexcept

生成函数、闭包调用、导入桥接和导出 façade 是 noexcept 边界。原生操作不必自己声明 noexcept，但异常逃出边界调用 std::terminate。构造、成员、运算符和生命周期操作同样适用。Carven try 不捕获原生异常。

需要继续执行时，在头文件、原生源或 cpp 片段的适配函数中先捕获异常，再通过选定接口返回应用结果。cpp 片段不会包围生成的 Carven 函数体。

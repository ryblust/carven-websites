需要使用原生类型或函数时，可以导入 C++ 头文件。Carven 检查自己的类型、访问和所有权，C++ 编译器继续检查原生声明、重载、构造和链接。需要明确声明两种语言之间的函数接口时，使用 `import(cpp)` 或 `export(cpp)`。

## 头文件和外部名字

以下片段展示选择形式；`provider.hpp` 和 `legacy.hpp` 由应用提供：

```carven
import <vector> using std::vector;
import "provider.hpp" using vendor::{ Widget, create };
import "legacy.hpp" using { Point, calculate };
import <vector> using std::*;
```

Carven 不解析头文件。没有 using 的导入不创建 Carven 名字。前导 `::` 直接选择 C++ 全局名字，可用于表达式、类型、显式转换和构造；Carven 不要求必须先导入头文件，C++ 检查声明实际可见性。

全局 C++ 路径、头文件选择路径和列表项，以及 `.`、`::`、`->` 后的成员名，可以使用形如标识符的 Carven 关键字，例如 `::vendor::async` 和 `handle.cancel()`。导入关键字拼写不会使它成为可直接使用的 Carven 标识符；通过全局路径或已绑定的非关键字前缀访问。Carven 拒绝 C++ 关键字集合中的原生名字，报告 `CV-CPP-IDENTIFIER`。

显式 `using` 把路径末尾的名字绑定到完整 C++ 路径。重复选择同一路径是合法的；末尾名字相同但完整路径不同则报错。显式选择优先于命名空间通配符导入；引用时，同一路径的所有显式导入都标记为已使用。同一路径的重载由 C++ 处理，没有跨路径重载合并。列表项只能是简单标识符，不支持别名、嵌套列表或列表内通配符。

局部绑定和模块声明遵循普通名字查找规则。外部导入不能与本模块的声明重名。普通查找未找到名字时，才到通过通配符导入的 C++ 命名空间中查找。外部名字只在当前模块生效，不通过 Carven 模块导入再导出。显式选择有未使用诊断，命名空间通配符导入没有。

## 类型、构造与转换

外部类型参数只能是类型，可嵌套。参数化 Carven 函数可以把类型参数用在 `::vendor::Box<T>` 等原生类型中，并通过 `::vendor::Box<T>::member` 使用静态成员。构造、成员访问、调用和转换在具体实例生成后交由 C++ 检查；Carven 源码直接对 `T` 进行复制或算术等操作，仍须在参数化函数体中有已知能力。`T { ... }` 对原生类型使用位置初始化，可以为空；原生构造必须显式写出类型，不能根据上下文推断。完整花括号构造的结果由 C++ 决定，包括模板实参推导和收窄检查，因此 `vector { 1, 2, 3 }` 推导为 `std::vector<int>`。

如果 Read 标量操作数的结果已经确定为常量，且不需要访问原变量的存储，原生构造就会接收该常量。这包括字面量、具名常量和经过常量折叠的标量表达式；表达式的副作用和失败仍会先执行。读取普通绑定仍保留存储访问，不构成原生常量表达式。函数签名和字段中的原生类型必须显式命名，局部所有者可从原生表达式推断。

当目标与值类型不同且至少一方为原生类型时，普通初始化、赋值、Read/Take 实参、返回、聚合元素和结果类型已知的值分支，都由 C++ 检查能否构造目标类型，包括窄化限制。Write 参数保留原存储，由 C++ 检查能否绑定到形参引用；仍需 `&` 和可写检查。显式 `as` 在任一方为原生类型时生成 `static_cast<T>`。

用作条件的原生值转换为 `bool`；`&&/||` 保留 Carven 短路。原生一元与非逻辑二元操作的重载和结果类型由 C++ 检查。推断为外部表达式类型后，即使 C++ 最终认为它是 int，Carven 也不自动认定等价于 `i32`。

C++ 检查原生构造是否可用。如果初始化前面的成员后，后面的成员初始化可能失败，生成代码可能先单独保存前面的成员，再在最终构造时复制或移动它。成员类型必须支持实际所需的复制或移动；也可以在原生适配器内完成整个聚合的构造。无需中间传递时，原位构造仍可接收不可移动的 prvalue。

## C 字符串

`c"text"` 产生外部 `const char*`，指向静态、不可变且以 NUL 结尾的存储。空字符串可用，内部 NUL 和 `\0` 非法。即使直接传给模板，也是指针而非字符数组。它不是 `str`，字面量模式拒绝它；根据上下文推断类型时，仍保留 `const char*` 类型，转换遵循上文的原生规则。

C 字符串可以初始化常量，并可在编译期执行中传参、复制、赋值和 Take；冻结保留其字节和指针类型，包括位于受支持聚合中的情况。相同完整字节内容在同一个链接域内共享在整个程序运行期间有效的不可变存储，包括跨生成模块和产物的情况。复制与重复字面量保留同一地址；导入的 C++ 指针遵守 C++ 实现的存储契约。无论在常量执行、解释执行还是原生执行中，打印和默认文本格式化都显示其文本。求值器不能读取未知原生内存，也不支持直接比较原生 C 字符串指针。需要按对象指针比较或显示地址时，可先显式 `as ptr<void>`，再遵循[擦除指针规则](/zh/reference/pointers/#类型擦除比较与显示)。原生插值使用相应 C++ formatter。`const char*` 和 `const void*` 是 C++ 写法，不是 Carven 类型语法；C 字符串绑定应像下例一样推导类型。

```carven
import <cstdio> using std::puts;

const greeting = c"hello";

puts(greeting);
println(greeting);
```

原生执行会打印两次 `hello`。

## 原生转换示例

以下两个绑定分别请求 C++ 目标构造和显式转换；C++ 检查各自的合法性：

```carven
import <vector> using std::vector;
let values = vector<i32> { 2, 4, 6 };
let count: usize = values.size();
let narrow = values.size() as i32;
println(count, narrow); // 3 3
```

## 访问与生命周期

未标记的实参使用 Read，`&` 为 Write，`&&` 为 Take。接收者的访问方式取决于其存储。用 C++ 返回的引用初始化局部变量时，仍会构造拥有自身存储的值，由 C++ 检查构造是否合法。原生成员与索引沿用根对象的访问方式；原生索引是否检查越界，由 C++ 实现决定。

Carven 检查已知所有者可用性、显式冲突和已知文本底层存储。它不推断 C++ 引用保留、指针存活或迭代器失效。已知可调用值借用和 Write 捕获不能传入没有声明接口契约的外部调用。原生引用绑定、指针算术和外部迭代协议不支持。

直接 C++ 调用可接收动态文本视图和包含它们的聚合，在实参求值和调用期间保护已知的底层存储。原生实现的作者与调用者负责长期保留、返回别名、重入和间接指针的生命周期。以 Write 方式传入保存视图的变量，并不表示它不再借用原来的底层存储。

原生调用、构造和表示转换的返回值不建立新的已知借用关系，即使返回 Carven 类型。`String` 不隐式变成原生字符串容器。

## `#[cpp]`

用围栏片段定义小型模块内实现。将以下完整示例保存为 `main.cv` 并运行 `carven main.cv`，调用者输出 `42`。

```carven
#[cpp] ---
inline auto native_answer() noexcept -> int {
    return 42;
}
---

println(::native_answer()); // 42
```

每个顶层片段原样进入实现文件，保持独立，不解析或插入 Carven 值，不绑定同名 Carven 声明。宏、重载、模板、链接、异常、对象生命周期、单一定义规则（ODR）和未定义行为均遵循 C++ 规则。

片段只进入实现，不向生成头文件发布声明。公开原生声明应放在头文件，公开 Carven 入口使用 export(cpp)。片段围栏不隔离宏或 pragma 状态，也不能配置此前已包含的头文件；不同原生编译环境应由构建系统管理独立 C++ 文件。

## 线程与共享状态

Carven 没有创建线程、在线程间共享状态或同步访问的源码操作。Read/Write/Take 与借用检查不建立跨线程安全。C++ 片段作者、import 的实现者和 export 的调用者负责并发调用、共享数据、同步与被引用对象的生命周期。

## 函数接口声明

```carven
private import(cpp) fn native_value(value: i32) -> i32;
```

`import(cpp)` 声明没有 Carven 函数体，可以标记为 private，也可以不标记可见性。默认调用同名的全局 C++ 函数，并采用声明中的参数访问方式。这一 C++ 函数称为 provider，即提供原生实现的函数。C++ 负责重载解析与模板推导。Carven 不生成 provider 的声明，也不解析或比较其 C++ 签名；作者与工具链负责声明可见性、定义、接口匹配和链接。不同模块中的同名导入仍是不同 Carven 能力。

可以独立绑定原生路径，使 Carven 函数名与 C++ provider 名不同：

```carven
private import(cpp) fn native_value(value: i32) -> i32 = ::vendor::compute;
```

目标是以 `::` 开头的限定名字路径，可含命名空间或静态成员；不能是任意表达式，不能写显式模板实参，也不经 Carven 导入或头文件 `using` 选择。C++ 检查声明、重载、模板和链接。

`export(cpp)` 是有体、对全批次可见并进入生成 API 的 Carven 函数：

```carven
export(cpp) fn value() -> i32 => 42;
```

不能直接导出 import(cpp)，需要普通包装函数。导入和导出均遵循普通函数的类型、访问、可见性、所有权与失败声明规则；`void` 单元值也可作参数或聚合元素；参数和聚合中的单元值使用 `carven::runtime::Void`，无失败的同步单元结果使用原生 `void`，可调用视图逃逸和公开类型可见性限制仍适用。

| Carven 契约                  | C++ 表示                                                             |
| ---------------------------- | -------------------------------------------------------------------- |
| 标量                         | 普通标量表示；`char` 为 char32_t                                     |
| `String` / `str`             | `carven::runtime::String` / std::string_view                         |
| 数组、元组、切片、区间、指针 | 生成的容器、元组、视图与指针类型                                     |
| 参数和聚合中的单元值         | `carven::runtime::Void`                                              |
| 结构体、枚举、具体闭包       | 生成的名义类型                                                       |
| 原生类型                     | 声明的 C++ 类型及其头文件环境                                        |
| 可调用视图                   | 声明签名对应的运行时可调用值表示                                     |
| Read                         | 普通 Read 策略：值快照或 `const` 引用                                |
| Write                        | 可变引用                                                             |
| Take                         | 拥有值；导出使用普通转移，导入转发原生右值                           |
| 无失败结果                   | 普通结果类型，包括 void                                              |
| 同步声明失败                 | `carven::runtime::Outcome<Result, Failures...>`                      |
| 异步完成契约                 | 冷 `carven::runtime::execution::AsyncOperation<Result, Failures...>` |

生成 API 头文件包含所需生成类型定义、原生头文件环境和运行时支持。调用方使用该头文件和匹配的运行时头文件，在 C++ 源码中调用接口。内部用于停止测试的控制流不计入导出函数的失败声明。若停止测试的控制流逸出原生入口，程序会终止；函数声明的失败仍通过 Outcome 返回。

provider 的作者与调用者负责生命周期、对象保留、重入和值有效性，包括 UTF-8 与 Unicode 标量。编译器不会为导入结果推断新的底层存储借用关系，原生 Write 调用也不能证明旧借用已释放。声明的回调可以在调用期间执行，但原生实现不能在借用生命周期结束后继续保留其可调用值存储。

直接导入且不声明失败的 `char` 结果，以及导出函数的 Read/Take `char` 参数，都会进行 Unicode 标量校验，无效时终止；这不是对聚合、指针、可变引用或 Outcome 的递归校验。

省略显式目标绑定时，provider 名不能是 `main`、`std` 或 `carven`。前导下划线的 C++ 保留规则由作者负责。导出 API 中符合 C++ 命名限制的名字保留原拼写；其他名字或以 `cv_escaped_` 开头的名字，使用该前缀加原始 UTF-8 字节的小写十六进制编码。不能原样使用的名字包括 C++ 关键字、含双下划线的名字、以 `_` 加大写字母开头的名字，以及 `stdin`、`stdout`、`stderr`。这些流名称在受支持的 C 运行库中可能是对象式宏。函数名不能与命名空间路径前缀冲突。

分阶段分析的函数体通过头文件导入或 import(cpp) 声明使用原生名字。只在 cpp 片段中定义的名字仍仅属于实现。有静态参数的函数不能跨声明式 C++ 边界。

## noexcept

生成函数、闭包调用、导入桥接和导出包装函数是 `noexcept` 边界。原生操作不必自己声明 noexcept，但异常逸出边界时会调用 std::terminate。构造、成员、运算符和生命周期操作同样适用。Carven try 不捕获原生异常。

需要继续执行时，在头文件、原生源或 cpp 片段的适配函数中先捕获异常，再通过选定接口返回应用结果。cpp 片段不会包围生成的 Carven 函数体。

原生适配器可显式返回与声明失败契约匹配的 Outcome；C++ 异常不会自动转换为 Carven 失败。

## 执行与初始化

头导入、源片段和收集的 cpp 不阻止解释或静态执行 Carven 代码；执行器不加载原生实现，也不运行 C++ 静态对象的动态初始化/析构。到达需要原生实现的操作才诊断。依赖这些原生副作用的程序须原生运行。

跨边界的 Read 参数遵循[普通 Read 传参规则](/zh/reference/ownership/#read-值与别名)。包含原生类型的参数使用 `carven::runtime::ReadArg<T>` 实现该策略。异步 provider 必须保存按值传入的 Carven Read 值；包含原生类型的参数对象会一直被借用，直到冷操作关闭。

C++20 协程帧至少保证 32 字节对齐，同时满足平台的基本对齐要求。需要在挂起期间保留的原生对象和临时值，不能要求更高的对齐；若需要更高对齐，应单独分配存储，并保留其所有者或借用。

## Provider 类型支持

含具体 import(cpp) 声明的模块生成 `carven/providers/<canonical/module>.hpp`，提供签名类型别名与完整依赖，包括模块私有名义类型，源可见性规则不变。别名位于 `carven::providers::<encoded module>::cv_escaped_functions::<encoded function>`。

`Result` 表示 Carven 结果类型的 C++ 表示，`Completion` 是原生函数实际返回的类型，`Parameter0` 等是形参值类型。`Failure0` 等表示失败载荷类型，按规范化后的失败集合顺序编号。`void` 的 `Result` 为 `carven::runtime::Void`；无失败的同步单元结果使用 `Completion = void`，异步 `Completion` 为冷 `AsyncOperation`。

在原生源文件或 `#[cpp]` 片段中包含该头文件来命名签名类型，并在 C++ 中另行声明 provider 函数。定义签名所用原生类型的头文件，不得反向包含依赖自身的生成 provider 头。该接口是 C++ 源码接口，不规定跨工具链二进制兼容性。

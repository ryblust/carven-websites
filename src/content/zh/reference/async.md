## 冷操作与 await

异步函数用于可能等待的工作，例如读取输入或等到某个时间。调用 `async fn` 先创建一个操作，函数体还不运行，因此称为冷操作。`await operation` 启动它、等待完成并取得结果。

若希望先启动工作、稍后再取结果，用 `async let child = operation;`。子任务的寿命由所在作用域管理，所以称为词法子任务：离开作用域之前，必须等它完成并清理。函数的 `-> T` 表示成功结果，`throw` 子句列出的失败在 await 时交付。

```carven
import std::async using yield_once;

async fn next(value: i32) -> i32 {
    await yield_once();
    return value + 1;
}

async fn main() {
    let operation = next(4);
    println(await operation);
    async let child = next(8);
    println(await child);
}
```

从 `std::async` 导入 `Operation` 后，可写 `Operation<T>`，或用 `Operation<T, throw Error + OtherError>` 同时声明结果和失败。成功类型与最终失败集合相同的操作具有相同类型，不取决于由哪个函数创建。泛型中的 `throw E` 代表失败集合参数，详见[失败契约](/zh/reference/failures/#失败集合参数)。

`Operation<void>` 与 `Operation<void, throw ()>` 都以单元值 `()` 成功，没有声明的失败。取消是另一种完成状态，不携带可由类型化 catch 选择的失败载荷。

一个冷操作只能启动和消耗一次。直接 await 在当前任务中运行被等待的工作，只有真正挂起或完成时才结束这段执行，不会因为写了 await 就自动让出执行机会。await 或启动子任务时，具名操作不需要 `&&`；普通所有权转移仍要写 `&&`。

操作不可复制或捕获，但可以按普通所有权规则放进局部绑定、字段、元组或固定数组。未使用的具名冷操作在作用域结束时销毁，函数体不会运行；单独写 `next(4);` 这样的冷操作表达式语句则被拒绝。异步成功结果不能再包含另一个操作。

同步函数可以接收和返回冷操作，前提是它借用的存储活得足够久。转移完整操作使用 Take 参数：

```carven
import std::async using Operation;

fn relay(&&pending: Operation<i32>) -> Operation<i32> => &&pending;
```

`await action()?` 先等待完成，再把声明的失败向外传播，普通 `try/catch` 可以处理这些失败。await 可出现在异步函数体，以及常量初始化器、const 块和编译期测试中；放入实参、返回或循环步进时，仍保持源码求值顺序。

## 冷组合

`when_all` 等待所有输入成功，`when_any` 选择第一个完成的输入，`first_successful` 选择第一个成功的输入。从 `std::async` 导入后直接调用；它们返回新的冷操作，构造时不会启动输入，也不能作为函数值传递。

下面保留前面的 next 定义，替换入口，并把新导入放在模块开头：

```carven
import std::async using when_all;

async fn main() {
    let results = await when_all(next(4), next(8));
    println(results.0, results.1);
}
```

| 组合                          | 成功结果                   | 选择规则                         |
| ----------------------------- | -------------------------- | -------------------------------- |
| `when_all(a, b, ...)`         | 按输入顺序的 `(A, B, ...)` | 所有输入成功                     |
| `when_any(a, b, ...)`         | `(usize, T)`               | 第一个完成，可能成功、失败或取消 |
| `first_successful(a, b, ...)` | `(usize, T)`               | 第一个成功                       |

when_all 保留嵌套元组和 void 元素的位置；空输入返回 `()`，单输入返回单元素元组。另外两种组合至少需要一个输入，且成功类型必须相同，返回的索引指向原始输入位置。声明的失败集合为所有输入失败的并集；取消保持独立。

实参按顺序各求值并转移一次。传入具名冷操作要写 `&&`，不能传已启动的词法子任务。构造后丢弃组合，或后续实参求值失败，都只销毁已保存的冷操作，不运行它们。

开始执行时，组合先按输入顺序启动全部操作，再运行排队的子任务。多个候选已经完成时按输入位置选择，否则按首次报告完成的顺序选择。when_all 遇到失败或取消后请求其他输入取消；首个选定的声明失败决定对外失败。若只收到子任务取消，仍等待可能到来的声明失败，没有失败才以取消完成。

when_any 保留选中的成功、失败或取消状态。first_successful 跳过失败和取消继续等待；若最终没有成功，转发首个选定的声明失败，所有输入都取消时才以取消完成。组合在启动前及对外交付前检查父任务取消，并在交付结果前等全部子任务完成清理。结果一旦确定，晚到的失败或取消不再替换它。

## 词法子任务与取消

`async let child = operation;` 把子任务放到同线程执行队列的末尾，当前作用域负责它的寿命。子任务不可复制或转移，可以 await 一次。正常离开作用域的每条路径，都必须 await 取得结果、close 关闭它，或写出取消请求。

`cancel child;` 只请求取消并立即返回，多次请求效果相同；它不等子任务结束，也不释放子任务仍需使用的存储。作用域结束时仍要等子任务完成清理。失败或取消导致的退出会自动请求子任务取消。return 等退出表达式先求值，再关闭子任务，因此表达式不能提前取走它们仍在借用的值。被调用函数只关闭自己启动的子任务。

cancel 是保留字，只接受具名词法子任务，不能用于冷操作、括号表达式或任意表达式。下面的片段放在使用 next 的异步函数体中：

```carven
async let child = next(8);
cancel child;
```

| 从 std::async 导入的操作               | 行为                                                       |
| -------------------------------------- | ---------------------------------------------------------- |
| `cancel_requested()`                   | 查询当前任务是否收到取消请求，异步执行外为 false           |
| `cancel_point()`                       | 返回冷 void 操作，执行时接受待处理取消请求                 |
| `yield_once()`                         | 返回冷 void 操作，执行时把后续工作排到队尾                 |
| `await wait_ready(first, second, ...)` | 等候某个子任务完成，返回输入索引与取消状态 `(usize, bool)` |
| `await close(child)`                   | 请求取消，等待结束，丢弃结果并释放该子任务的借用           |

这些内建操作遵循普通名字查找，只能直接调用。创建 yield 或取消检查点并不会执行它；检查点在启动时读取请求，yield 本身不接受取消。同步辅助函数可以观察调用它的异步任务的取消状态。取消需要任务配合：一直不到达接受取消的操作，就可能一直延迟清理。

## 等待终态与显式关闭

子任务不再运行、已经成功、失败或取消时，称为到达终态。`wait_ready` 等这个状态，但不取走结果；`close` 则等它结束并丢弃结果。两者都必须直接写在 await 后面，参数须为本次函数调用中启动的具名子任务，不能先存成操作或函数值。候选可以有不同结果和失败类型。

以下片段接续 next 定义，语句放在异步函数体，导入放在模块开头：

```carven
import std::async using { wait_ready, close };

async let first = next(4);
async let second = next(8);
let (index, cancelled) = await wait_ready(first, second);
if index == 0 {
    await close(second);
    if cancelled { await close(first); } else { println(await first); }
} else {
    await close(first);
    if cancelled { await close(second); } else { println(await second); }
}
```

wait_ready 至少需要一个候选，每个候选都必须确定尚未消耗；重复候选或只在部分路径已被消耗都无效。它不消耗结果、不释放借用，也不满足正常退出时的观察要求，多次等待可能选中同一子任务。

返回的索引和 bool 来自同一次状态观察。false 表示该任务成功或携带声明的失败，可以再 await 取得结果。多个任务已经完成时取输入位置最小的；否则取第一个报告终态的，即使父任务恢复执行前其他任务也已结束。

close 等子任务完成后丢弃成功、失败或取消状态，标记它已消耗并释放其借用。已经消耗的子任务再 close 不做任何工作，包括只有部分路径先前取得结果的情况。不能 close 尚未启动的冷操作。

这两种等待都不因父任务取消请求而提前结束，请求仍可被查询。它们也不掩盖运行时终止、预算超限或原生接口违规。若子任务不配合取消，等待可能持续很久；编译期执行使用同样规则。

## 保留访问与准入

操作可能在创建之后才使用输入，所以它需要的存储必须保持存活。创建操作、启动子任务或请求取消都不会自行结束这段借用；取得完成结果或 close 完成后，才释放相应借用。作用域仍负责子任务自身的清理。

| 参数形态      | 支持的输入                                                                   |
| ------------- | ---------------------------------------------------------------------------- |
| Read 或 Write | 标量、SIMD 向量、掩码、void                                                  |
| Read          | 由这些纯 Carven 值组成的结构体、元组和枚举；原生对象也可按下面的借用规则传入 |
| Take          | 自己拥有内容、且不引用外部存储的值                                           |

Read 标量在创建冷操作时保存快照；Write 保留调用者的原存储。Write 不是独占借用，允许的修改仍可继续，但借用结束前不能 Take 或重建被保留的整个所有者。

原生 Read 参数保留源对象，这也适用于嵌在 Carven 聚合中的原生对象。源对象须有已知存储，例如具名变量；原生临时值或返回引用的查询不能单独建立这种保证。操作完成或关闭前不能取走或替换被保留的对象，隐藏在对象内部的资源则由原生实现保证寿命。

借用文本、切片、指针、可调用视图，以及无法证明独立拥有内容的原生 Take 输入不受支持。泛型定义先检查已知不合法的形态；依赖未知类型参数的条件，再对具体类型检查。未知类型本身不能证明可复制或具有独立存储。

`async fn main(args)` 的可选参数有专门的入口规则：它借用入口包装器拥有的 `Vector<String>`，包装器一直保留到根任务和子任务关闭。普通异步 Read 参数仍遵循上面的限制。

编译器检查源码能表达的借用、破坏性访问和逃逸。原生 Write 按可能使所选存储失效来检查；原生实现仍负责隐藏引用、重入和有效值，编译器不检查它的 C++ 函数体。结果存储可以在原位保存不可移动的值。

异步函数调用的同步辅助函数，不能通过 require 或 fail 停止测试；创建冷操作与执行其函数体分开检查。执行器单线程且不可重入，深 await 链不会无限增加原生栈，但协作调度不保证公平或取消时延。异步测试、带实例接收者的异步类操作、异步函数值、任意外部 awaitable 类型和跨线程恢复均不支持。

## 静态参数与执行

异步函数可声明 `const name: T` 参数。调用时计算并保留这些静态实参，为对应值选择函数版本；生成的调用和冷操作只保存运行时实参，各版本仍遵守原函数的成功与失败契约。

`const async fn` 还允许编译期执行：

```carven
const async fn next(value: i32) -> i32 => value + 1;
const answer = await next(4);
```

创建冷操作只保存输入，await 才消耗操作并运行函数体。局部操作、Write 访问、失败传播与清理都沿用普通规则。私有同步 const fn 可以返回推断出的冷操作，但同步函数体不能 await；常量初始化器、const 块和编译期测试可以等待操作。操作只属于当前执行过程，不能作为完成的常量保留下来。

编译期执行支持带 const 修饰的源码函数、作用域管理的子任务及异步内建操作。启动子任务和 yield 使用先进先出队列，直接 await 留在当前任务。一次常量求值中的任务共享预算；输入、时钟和等待使用编译器进程的宿主能力，不加载原生 C++ 实现。运行时调用同一源码函数则使用 C++ 协程。

## 原生提供者与宿主

这一节面向编写 C++ 异步实现或宿主的读者。`import(cpp) async fn` 声明返回冷 `carven::runtime::execution::AsyncOperation<Result, Failures...>` 的原生函数，源码中的结果和失败类型描述的是操作完成时的结果。`export(cpp) async fn` 在模块的 C++ API 头中提供同样表示。

宿主管理事件源和原生资源，把上下文传给导出的根函数，并调用 `drive_root(operation, &source)`。Read 上下文是 const 引用借用；上下文对象及其隐藏资源须一直存活到冷操作被丢弃，或执行与子任务清理全部结束。请求取消不代表回调已停止，任何仍可能被待处理或正在执行的回调访问的状态，都必须继续保留。

原生等待对象使用 `carven/runtime/execution/execution.hpp` 的 `ResumeContinuation` 保存挂起协程的恢复信息。它查询取消请求、确定完成结果，然后把恢复工作交给执行器队列。事件在执行器线程交付，不直接从回调恢复 Carven 代码。

宿主的 `EventSource` 实现 `poll(Driver&) noexcept` 与 `wait(std::optional<std::int64_t> deadline) noexcept -> bool`。poll 发布已经就绪的完成并排队；wait 在没有待处理原生请求时返回 false，否则等待事件或指定的单调时钟纳秒期限，并返回 true。

单事件源可以直接等到就绪或最近的计时器；有多个独立事件源时，每次等待最多十毫秒，以便依次轮询。标准输入有待处理读取时注册自己的事件源。`Driver::attach` 到 `detach` 之间，事件源对象必须保持存活。原生取消在执行器线程调用 `TaskContext::request_cancel()`，以便通知正在等待的计时器。

await 收到成功 char 时会检查 Unicode 标量有效性，即使结果被丢弃也如此。失败和取消先转移，不接收成功值；销毁未启动的冷操作也不接收结果。组合会在保留选中值或确定最终结果前检查成功的 char，包括后续输入失败的 when_all。原生 C++ 类型继续遵循它们自己的值有效性要求。

本地运行源码用 `carven main.cv`，只做语义检查用 `carven check main.cv`，生成 C++ 用 `carven compile`。`carven interpret` 无需原生 C++ 构建，可直接执行受支持的 Carven 操作。语义检查也会执行源码要求的编译期工作。本页说明输入收集、产物目录和已检查程序的复用。

## 命令总览

```sh
carven main.cv -- argument
carven --tests main.cv
carven check --timings main.cv
carven check main.cv -o build/checked
carven compile build/checked -o build/program
carven compile build/checked --tests -o build/tests
carven compile --stdout main.cv
carven interpret --trace --max-steps 100000 main.cv
carven interpret --tests main.cv
carven dump tokens main.cv
carven dump ast main.cv
```

用 `carven --help` 或 `carven -h` 查看总帮助，用 `carven compile --help` 等形式查看子命令帮助。`carven --version` 和 `carven -V` 输出版本号；不带实参时输出总帮助并成功退出。

## 源码收集

处理源码时，命令把显式指定的应用 `.cv` 文件与两处自动收集的源码合并：匹配工具链的 `crafts/carven/`，以及工作目录中可选的 `crafts/`。收集递归选择 `.cv` 和 `.cpp` 文件，不递归进入目录符号链接。文件按规范物理路径去重，不同文件不能有相同的规范化模块路径。

普通源码调用至少需要一个显式 `.cv` 输入；`check` 和 `compile` 也可使用后文的映射或保留分析目录。`import` 只在已收集模块和编译器提供的声明中解析，不查找或下载更多文件。

所有收集的 `.cv` 源码都会接受检查，并完成所需的编译期求值与 `const test`，包括未导入模块及收集根内的 `examples/`、`tests/`。安装的源文件须能共同构建；独立入口示例和故意无效的测试应放在收集根外。

外部仓库可放在 `thirdparty/` 等收集根外的位置，再显式选择所需 `.cv` 文件。原生源文件、头文件路径、宏、编译选项和链接库由构建系统配置。

## 语义检查

`check` 完成语义分析及必需的常量初始化、常量块和 `const test` 执行，不要求程序入口。普通函数和运行时测试只接受语义检查，不在该阶段执行。

不指定 `-o` 时不写产物；`-o <dir>` 保留语义中间表示和清单（manifest）。检查不生成 C++ 或选择原生链接域；原生重载、模板与类型属性由后续 C++ 编译检查。

`check` 接受源码或保留语义目录，以及 `--source` 映射、`-o` 和 `--timings`。成功时返回 0，并在 stderr 输出 `carven: check passed`；错误返回 1，警告不改变成功状态。

## 阶段计时

`check`、`compile`、`interpret`、`dump` 和直接运行都支持 `--timings`。报告在 stderr 显示结果、总耗时和实际尝试的阶段，包括失败路径。语义分析时间包含静态执行，原生运行还报告 C++ 编译和链接。总耗时包含准备、诊断和清理，可能大于列出的阶段之和；嵌套的语义细分时间不能再次加到语义总时间中。无效选项不生成计时报告，程序与产物输出流保持原用途。

## 直接原生运行

先准备可用的 C++20 编译器、SDK 和链接器。环境变量 `CXX` 指定单个编译器名称或路径，默认是 `clang++`；不能在其中附加编译选项。MSVC 风格和 GCC 风格的驱动分别使用对应参数。

直接运行命令先分析源码、生成 C++，再在独立系统临时目录编译全部生成实现和收集的原生源，最后运行程序；这个流程无需 Xmake。

安装布局中，`bin/carven` 和匹配的 `crafts/carven/` 位于同一安装前缀下。临时运行目录在命令返回后清理，强制终止可能留下该目录。子进程继承工作目录、环境和标准流；`--` 后的实参原样传给程序，包括空实参、空格和引号。

执行要求一个程序入口。命令返回原生编译器的失败状态或程序的退出状态；POSIX 信号终止转换为 `128 + signal`。复杂依赖与增量构建由外部构建系统管理。Windows 原生执行会链接标准 TCP 实现需要的 Winsock 库。

`--tests` 运行普通测试并跳过程序入口，要求至少一项运行时测试；编译期测试先在分析阶段执行。测试失败返回非零状态。断言、停止与报告规则见[入口与测试](/zh/reference/entry-testing/)。

## 解释执行

解释器先完成普通语义分析和必需的静态执行，再执行已检查程序，不写出 C++ 或原生可执行文件。未使用函数也接受普通语义检查；`const fn` 还在定义处检查静态执行能力。运行时到达不支持的操作时产生诊断。

解释执行支持局部值、聚合、元组、`Vector`、文本、字符遍历、控制流、类型化失败、局部指针及受支持的异步组合，也支持输入配置与读取、时钟采样、等待和截止时间组合。

显式静态执行在 `check`、`compile`、原生运行准备及 `interpret` 的分析阶段完成宿主操作；普通调用在程序执行阶段完成。同一编译器进程共享输入游标，编译期读取的预读字节、EOF 状态和系统错误会保留到后续解释执行。

收集的 `.cpp` 文件、头文件导入与源片段不阻止解释；解释器不编译或加载它们，也不运行 C++ 静态对象的动态初始化与析构。到达不支持的原生操作或可调用实现时，报告 `CV-INTERPRET-ADMISSION`。依赖原生副作用的程序需要原生运行。解释入口必须无参数，`--` 后的实参被忽略。

`--trace` 在 stderr 输出解释执行的语句位置、函数调用与成功返回，不跟踪此前的静态执行，也不记录每个表达式和值。

`--max-steps N` 接受非负十进制整数，默认 100,000。解释入口与其中的嵌套调用共享执行预算；它限制求值步数，不限制实际耗时或阻塞 I/O。值大小、文本、聚合和深度限制也适用。每次编译期求值另有独立预算，不受该选项影响。重复指定 `--trace`、`--tests` 或 `--max-steps` 是错误。

`interpret --tests` 按规范模块顺序及同一模块内的源码顺序运行，每个测试使用新存储和独立预算。`require`、`fail` 的停止不能由类型化 `catch` 捕获。普通执行错误或预算耗尽停止当前测试，后续测试继续；断言失败或运行时陷阱中止整个执行，不输出完成汇总。正常结束时，stderr 报告通过和失败的测试数量。

## 输入路径

源码路径使用 UTF-8、`/` 分隔符和 `.cv` 扩展名。应用路径必须相对工作目录，词法归一化后不能越出该目录。去掉扩展名并用点连接路径组件得到模块名，例如 `src/main.cv` 对应 `src.main`。每个组件须形如标识符，也可使用关键字拼写。

工具链及已知 Crafts 根内的文件按所属根确定模块身份，不受安装前缀影响。其他绝对输入路径必须包含 `crafts/` 层级，例如 `/opt/packages/crafts/json/parser.cv` 对应 `crafts.json.parser`。

`compile` 和 `check` 支持可重复的 `--source=<canonical-module>=<path.cv>`，可与作为位置参数传入的源码混用。至少提供一个源码位置参数或映射。映射独立指定物理文件的模块身份，例如 `--source=app.main=/work/src/main.cv`。

使用映射时，调用者必须显式列出本次要编译的全部源码。命令仍加载工具链源码，但不自动发现项目 Crafts。相同物理文件会去重；一个文件被指定冲突身份，或不同文件拥有相同模块身份时，命令拒绝该批次。

## compile 产物

`check -o <dir>` 写出语义中间表示和 `carven/manifest.json`。`compile` 默认在工作目录写出 C++ 和清单，使用 `-o <dir>` 可选择目录；`--stdout` 只显示供人工检查的文件标题与内容，不写文件、清单或语义中间表示。目的地选项只能选择一项，不能重复。

写出时创建父目录并覆盖同名旧文件，首次 I/O 失败后停止；此前的文件可能已经改变。构建系统负责目录隔离、旧文件清理与发布保护。

`compile` 只为本次调用拥有的输入生成实现：显式源码和项目 Crafts 属于自有输入，自动加载的工具链源码属于依赖。显式提供安装源码时，该文件也成为自有输入。

`--stdout` 展示显式输入或所给分析目录中的自有产物，以及所需的共享接口和请求的测试入口；依赖保持为 `#include`。输出含文件标题，不能作为单个 C++ 文件编译。

只传入保留分析目录时，`compile` 从已检查程序生成 C++，不重新解析、分析或执行静态代码。同一分析结果可生成普通程序和测试程序。

仅含标准库的分析目录还可伴随新源码输入，为泛型和静态函数提供已检查定义。使用这些定义的项目在分析时检查新实例，不能重定义这些标准模块。构建系统负责确认源码、依赖产物和编译器是否发生变化。

[产物清单](/zh/reference/toolchain/#产物路径)列出输入、输出、归属、测试数与可缓存性。`--stdout` 不写清单或语义中间表示。

## 链接域

每个原生目标使用自己的输出目录。生成接口的链接身份与公开 API 名字规则见[构建产物](/zh/reference/toolchain/#产物路径)。

## 测试产物

`compile` 默认不生成运行时测试。`--tests` 生成模块测试函数、运行器头和测试入口，并省略程序入口包装函数。`--tests=runner` 生成测试函数和运行器，保留程序入口包装函数，由集成方选择进程入口和报告器。两种模式互斥且不能重复指定。生成允许空测试集，运行测试的命令要求至少一项运行时测试。

## 诊断与编译期输出

错误写入 stderr，命令返回非零；警告不改变成功状态。stderr 支持终端样式时默认使用颜色；`NO_COLOR` 非空、`TERM=dumb` 或 stderr 被重定向时不着色。

静态执行的 `print`、`println` 写入 stdout，`eprint`、`eprintln` 写入 stderr。`compile --stdout` 把全部静态程序输出转到 stderr，将 stdout 留给生成产物。后续失败不撤销已完成输出，复用保留分析或生成产物时不重放静态输出。

`dump` 只加载一个文件并进行词法与语法分析，不做语义分析、不执行静态测试，也不生成产物。默认依次输出 `Tokens` 和 `AST`，也可选择 `tokens` 或 `ast`。词法错误阻止语法分析；语法错误会保留此前打印的 token，但不打印 AST。

静态与解释执行诊断最多列出八个调用点，并报告省略数量。源码错误按同一文件中的源码顺序显示；每个函数、测试和 `const` 块独立报告首个错误。如果某个函数的结果类型或失败集合推断失败，依赖这些信息的函数体会等到问题修复后再检查。

## carven-format

carven-format 是独立的源码格式化工具，不是 `carven` 子命令。在 Carven 仓库根目录运行 `./xmakew build carven-format` 构建；以下命令也可通过 `./xmakew run carven-format` 调用。

| 命令                               | 行为                                          |
| ---------------------------------- | --------------------------------------------- |
| `carven-format [FILE 或 -]`        | 格式化单个输入到 stdout；省略输入则读取 stdin |
| `carven-format check FILE/DIR ...` | 在 stdout 列出需要格式化的路径，不写文件      |
| `carven-format check -`            | 检查 stdin；有差异时报告 `stdin`              |
| `carven-format write FILE/DIR ...` | 静默替换有变化的文件                          |
| `carven-format help [COMMAND]`     | 查看帮助或指定命令的帮助                      |

`check` 和 `write` 必须指定输入；当前目录写为 `.`。stdin 必须单独使用，不能用于 write。只有第一个实参识别命令名；默认模式读取同名文件时使用 `./help`、`./check` 或 `./write`。没有选项；包括 `--help` 和 `--` 在内，以短横线开头的实参都是字面路径。

目录递归选择 `.cv` 文件，跳过嵌套的隐藏目录、构建目录和符号链接项；显式文件不限制扩展名。路径排序并去重，检查结果尽可能使用相对当前目录的路径。显式文件符号链接可读取，但 write 拒绝写入。

退出码为 0（成功）、1（check 发现差异）、2（错误）；诊断写到 stderr。整批源码通过词法与语法验证后才报告变化或写入。每个变化文件在目标旁暂存，保留权限位，并在替换前比较原始字节。后续 I/O 失败可能留下已更新的文件；字节比较不锁定文件。未变化文件不重写。

固定风格使用四空格缩进与 100 字节目标行宽；UTF-8 可能较早换行，不可拆分 token、注释、C++ 片段和类型实参可能超宽。保留 token/字面量拼写、导入尾逗号以外的标点、注释文字及 token 间位置、插值文本/规格和 C++ fence 字节；插值字段中的表达式会格式化。多行字符串 token 字节保留语义布局。常量块和静态控制沿用普通块/控制头风格。作者空行最多连续保留一行，清除受保留 token 之外的空行空格，普通行尾归一化为 LF，非空输出以换行结束。输出在返回前重新词法分析、比较并解析。

导入选择列表的单行形式在花括号内各留一个空格，不保留尾逗号，如 `using { Point, length }` 和 `using std::{ vector, allocator }`。多行形式每行一个名字，并添加尾逗号；已有尾逗号本身不会强制换行。`::` 与后面的花括号紧邻。这是格式化规则，解析器仍接受可选的尾逗号。

格式化不解析 import、不做类型检查，也不执行编译期函数或测试。格式化成功仅表明源码满足格式化器的语法与保留检查。

当前固定样式展开非空 struct/enum 与多字段具名构造；相邻布局相同且不超宽的单行构造按列对齐；不同顶层项类别之间分隔。移除紧邻定界符内侧、没有注释的空行。完整样式定义见主仓库 tools/format/README.md。

## 绑定与访问

局部 let/var 绑定拥有自己的值，负责让值存活到作用域结束，这样的绑定称为所有者（owner）。str 或切片则借用其他值的存储，不能延长其生命周期。复制 String 得到独立文本，复制视图仍指向原文本。

Read、Write、Take 分别表示函数可以读取实参、修改调用者已有存储，或接收值的所有权。访问权限与值的类型分开判断。参数/实参的 & 与 && 是访问标记，不构造引用类型；`ptr<&T>` 内 & 则是指针目标权限。

| 形式                | 角色                           |
| ------------------- | ------------------------------ |
| let / var           | 不可重赋值 / 可变运行时所有者  |
| 局部 const          | 静态绑定                       |
| 无标记参数          | 不接收所有权的 Read            |
| & 参数              | 不接收所有权、非独占的 Write   |
| && 参数             | 转移给不可变所有者的 Take      |
| 无标记 / & 范围绑定 | 元素 Read / 来源可写时 Write   |
| 无标记 / & 模式绑定 | 选中值 Read / 主体可写时 Write |

初始化、遮蔽、丢弃绑定和元组目标见[变量声明与作用域](/zh/reference/bindings/)。

调用时必须写出与参数相同的访问标记：read(value)、write(&value)、take(&&value)。Write 不独占，同一所有者可同时传多个 Write 参数；实参从左到右，别名写入按函数体执行顺序生效。Read 只禁止修改参数当前存储，内部指针与 Write 捕获保留独立权限。

## Read 值与别名

Read 表示函数不能通过该参数写入值，但不保证总是复制实参。标量等纯 Carven 值在实参求值时保存快照；含数组、Vector、String 或闭包存储的值通过 const 引用保留原存储，包括嵌在聚合中的情况。含原生对象时，只有 C++ 复制构造和析构都是平凡操作（trivial）时才按值传递，否则使用 const 引用，不按对象大小选择。

如果返回结果或外部状态需要继续引用参数对象，整个调用链都保留该对象的 const 引用，包括实参临时值与原生包装函数。异步调用中，包含原生类型的 Read 参数对象从冷操作构造到关闭期间始终被借用。import(cpp)、export(cpp) 和可调用视图使用同样策略；要求稳定原生存储的目标，不能适配为缺少该借用要求的视图。

模式和范围循环中的 Read 绑定也使用相同选择：纯值保存快照，具有内部存储的值借用被匹配的值或当前元素。因此，引用方式的 Read 可能观察到其他别名后续写入的内容；需要独立值时先显式复制。复制值内部已有的视图仍引用原存储。无论按值还是引用，访问标记和 Take 冲突检查都相同。

## Take 与可用性

let、var 与 Take 参数是所有者。Take 参数是不可变所有者，可继续 Take。Read/Write 参数、模式/范围绑定、捕获状态和 const 不能作为 Take 源。Take 的操作数必须是完整所有者或临时值，不能 Take 仍可用完整所有者的字段或元素。

```carven run
fn relay<T>(&&value: T) -> T => &&value;

var values: Vector<i32> = [1, 2, 3];
let moved = relay(&&values);
values = [4, 5];
println(moved.length(), values.length()); // 3 2
```

递归元组参数与循环目标继承这些规则。Take 参数里的名字为独立不可变所有者；Read/Write 绑定仍访问完整参数或元素的对应部分。局部元组解构创建独立元素所有者。位置字段 .0 与命名字段有相同完整所有者限制。

从拥有存储的临时值中取字段时，会按值返回该字段。`(&&owner).field` 先转移整个所有者，再取字段；源仅求值一次，完整值保留到完整表达式结束，其他字段正常清理。`owner.field` 只是 Read，不会转移所有权。不能返回指向即将销毁的临时内容的视图。

Take 即使对可复制类型也令源不可用；生成 C++ 操作须保留所有权与可观察效果。返回具名所有者要求复制该值；需要转移时写 `return &&owner;`，返回本身不隐式选择 Take。CV-LINT-RETURN-COPY 在所有调用上下文允许 Take 时提示含 String 且无原生成分的返回复制；`return &&owner;` 显式转移。

完整 var 的普通赋值仅在右侧成功后恢复可用性；字段赋值、复合赋值与更新要求旧值可用。先执行条件中的操作，再根据能够确定的 bool 结果分析所有权路径；未知条件合并所有可能路径，循环分析同时考虑零次迭代和从循环体返回循环头的路径。`x = relay(&&x)` 成功可恢复 x，失败仍不可用；`x = &&x` 含括号形式非法。

## 复制与转移

源级 Take 是可用性状态变化，不承诺固定数量的原生 move。通过 Read 初始化所有者会复制值，源保持可用；&& 转移，源失效；独立临时可直接交付。外部 C++ 类型的实际构造、赋值、移动和析构合法性由原生编译器检查。

## 未完成访问与冲突

Take 不能与尚未完成的调用所保留的存储位置访问冲突，包括被调用函数和外层实参。独立结果不再保留输入访问：f(x + 1, &&x) 或返回独立值的 f(identity(x), &&x) 可合法，f(x, &&x) 始终冲突，与 Read 传值策略无关。

值捕获快照完成后独立，但创建时源须可用；捕获和范围绑定不支持 Take。Write 捕获会持续到所有直接或间接持有该闭包的对象生命周期结束。放入聚合、访问其成员、作为控制表达式结果、复制或转移，都会保留这种关联；只要仍有对象持有该闭包，就不能 Take 被捕获的源对象。

## 赋值与生命周期

成员/元素可写性继承接收者。普通赋值使用 C++ 赋值操作，不会先结束对象生命周期再重建对象；先选目标再求新值，各一次。数值复合赋值要求对应的数值类型类别，位运算/余数/移位及自增减要求整数。

复制值时会复制其直接拥有的成员，包括结构体字段、数组元素与枚举载荷；str、切片、可调用视图或 Write 捕获只复制借用信息，不复制或延长底层存储。局部所有者在其词法作用域结束时销毁，正常退出和控制转移都会结束其生命周期。临时属于完整表达式，除非 match 主体或范围源等构造显式保留。将结果保存到生命周期更长的所有者中，不会延长结果借用的底层存储。语言不提供源级析构函数或一般的生命周期延长语法。

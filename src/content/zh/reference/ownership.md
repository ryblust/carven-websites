## 绑定与访问

局部 let/var 绑定拥有自己的值，负责让值存活到作用域结束，这样的绑定称为所有者（owner）。str 或切片则借用其他值的存储，不能延长其寿命。复制 String 得到独立文本，复制视图仍指向原文本。

Read、Write、Take 分别表示函数可以读取实参、修改调用者已有存储，或接收值的所有权。访问权限与值的类型分开判断。参数/实参的 & 与 && 是访问标记，不构造引用类型；`ptr<&T>` 内 & 则是指针目标权限。

| 形式                | 角色                           |
| ------------------- | ------------------------------ |
| let / var           | 不可重赋值 / 可变运行时所有者  |
| 局部 const          | 静态绑定                       |
| 无标记参数          | 非拥有 Read                    |
| & 参数              | 非拥有、非独占 Write           |
| && 参数             | 转移给不可变所有者的 Take      |
| 无标记 / & 范围绑定 | 元素 Read / 来源可写时 Write   |
| 无标记 / & 模式绑定 | 选中值 Read / 主体可写时 Write |

声明必须有初始化器，可选注解须兼容。精确 `_` 不建名字，可重复且不参与未使用警告，运行时值仍求值并保留到作用域结束；`_name` 是普通名字。模块 const 必须具名。局部目标在类型、初始化器及所需常量完成后才发布，因此初始化器可选择同名外层绑定。

调用须重复访问：read(value)、write(&value)、take(&&value)。Write 不独占，同一所有者可同时传多个 Write 参数；实参从左到右，别名写入按函数体执行顺序生效。Read 只禁止修改参数当前存储，内部指针与 Write 捕获保留独立权限。

## Read 值与别名

Read 表示函数不能通过该参数写入值，但不保证总是复制实参。标量等纯 Carven 值在实参求值时保存快照；含数组、Vector、String 或闭包存储的值通过 const 引用保留原存储，包括嵌在聚合中的情况。含原生对象时，只有 C++ 复制构造和析构都平凡才按值传递，否则使用 const 引用，不按对象大小选择。

如果返回结果或外部状态需要继续引用参数对象，整个调用链都保留该对象的 const 引用，包括实参临时值与原生包装函数。异步原生 Read 参数从冷操作构造到关闭都保留源对象。import(cpp)、export(cpp) 和可调用视图使用同样策略；要求稳定原生存储的目标，不能适配为缺少该借用要求的视图。

模式和范围循环中的 Read 绑定也使用相同选择：纯值保存快照，含存储值借用所选主体或元素。因此，引用方式的 Read 可能观察到其他别名后续写入的内容；需要独立值时先显式复制。复制值内部已有的视图仍引用原存储。无论按值还是引用，访问标记和 Take 冲突检查都相同。

## Take 与可用性

let、var 与 Take 参数是 所有者。Take 参数是不可变 所有者，可继续 Take。Read/Write 参数、模式/范围绑定、捕获状态和 const 不能作为 Take 源。初始 Take 操作数须为完整所有者或临时，不能 Take 仍可用完整所有者的字段或元素。

```carven
fn relay<T>(&&value: T) -> T => &&value;
var values: Vector<i32> = [1, 2, 3];
let moved = relay(&&values);
values = [4, 5];
println(moved.length(), values.length());
```

递归元组参数与循环目标继承这些规则。Take 参数里的名字为独立不可变 所有者；Read/Write 名字仍投影完整参数或元素。局部元组分解创建独立元素 所有者。位置字段 .0 与命名字段有相同完整所有者限制。

拥有值的字段投影按值交付。`(&&owner).field` 先消费整个 所有者，再取字段；源仅求值一次，完整值保留到完整表达式结束，其他字段正常清理。`owner.field` 只是 Read，不消费。不能返回即将销毁的临时内容的 view。

Take 即使对可复制类型也令源不可用；生成 C++ 操作须保留拥有权与可观察效果。返回名字默认复制，return 不暗示 Take。CV-LINT-RETURN-COPY 在所有调用上下文允许 Take 时提示含 String 且无原生成分的返回复制；`return &&owner;` 显式转移。

完整 var 的普通赋值仅在右侧成功后恢复可用性；字段赋值、复合赋值与更新要求旧值可用。条件先执行效果，再用已证明 bool 正常结果选择所有权路径；未知条件合并所有可能路径，循环包括可能零次及回边。`x = relay(&&x)` 成功可恢复 x，失败仍不可用；`x = &&x` 含括号形式非法。

## 拥有字段投影

先消费完整积再选字段与直接 Take 字段不同；嵌套投影遵循同样规则。元组分解可同时建立多个独立元素 所有者，元数与嵌套须匹配。取走一个分解名字不影响其他名字。

## Take 与 C++ move 的契约

源级 Take 是可用性状态变化，不承诺固定数量的原生 move。Read 初始化所有者复制，源保持可用；&& 转移，源失效；独立临时可直接交付。外部 C++ 类型的实际构造、赋值、移动和析构合法性由原生编译器检查。

## 未完成访问与冲突

Take 不能与尚未完成调用保留的 place 访问冲突，包括被调用函数和外层实参。独立结果不再保留输入访问：f(x + 1, &&x) 或返回独立值的 f(identity(x), &&x) 可合法，f(x, &&x) 始终冲突，与 Read 传值策略无关。

值捕获快照完成后独立，但创建时源须可用；捕获和范围绑定不支持 Take。Write 捕获与每个直接或间接包含该闭包的活持有值的对象同寿命，放入聚合、投影、控制结果、复制或转移都保留关联；只要持有值的对象仍活，不能 Take 捕获源。

## 赋值与寿命

成员/元素可写性继承 接收者。普通赋值使用 C++ 赋值，不结束对象寿命再重建；先选目标再求新值，各一次。数值复合赋值要求对应数值族，位运算/余数/移位及自增减要求整数。

复制拥有直接成员，包括结构字段、数组元素与枚举载荷；非拥有 str、slice、可调用视图 或 Write 捕获不克隆、不延长 后备存储。局部所有者活到其词法作用域结束，正常退出和控制转移都结束寿命。临时属于完整表达式，除非 match 主体或范围源等构造显式保留。把结果交付到长寿命所有者不延长结果所借 后备存储。没有源级析构或一般寿命延长语法。

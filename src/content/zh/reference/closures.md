lambda 是匿名函数，写作 `[captures](parameters) => expression` 或 `[captures](parameters) { statements }`。用省略类型注解的绑定保存具体闭包值；需要调用回调的函数可以用 `fn(...) -> R` 参数。

## 值捕获与 Write 捕获

```carven
var offset = 2;
let saved = [offset](value: i32) => value + offset;
let live = [&offset](value: i32) => value + offset;

offset = 5;
println(saved(3), live(3)); // 5 8
```

`saved` 拥有创建时捕获的值 `2`。`live` 保留对原 `offset` 的 Write 访问，调用时读取更新后的值 `5`；保留 Write 访问不要求一定执行写入。完全不捕获的 lambda 使用 `[]`，例如 `[](value: i32) => value * 2`。

## 创建与捕获

lambda 必须写捕获列表，空列表写 []。函数体可以是块或 `=> expression`，表达式体遵循具名函数的返回规则。创建不执行函数体；捕获按列表顺序建立，每个名字一次，源为可见运行时绑定。不能显式捕获模块声明或常量。局部常量只有在检查 lambda 函数体时能确定值，才可不捕获而直接使用；依赖未绑定外围静态参数的常量不能跨越该边界。可以先用该值初始化运行时 let，再显式捕获它。

| 形式        | 捕获内容           | 体内权限 |
| ----------- | ------------------ | -------- |
| `[value]`   | 创建时所选值的副本 | Read     |
| `[&value]`  | 可写源存储的别名   | Write    |
| `[&&value]` | 不支持             | 编译错误 |

值捕获不可赋值，也不能 Take；Write 捕获也不能 Take 捕获绑定。每一层嵌套 lambda 都有独立捕获边界。未使用的显式捕获产生 `CV-LAMBDA-CAPTURE-UNUSED`。创建表达式不贡献闭包体的失败；实际调用使用其失败契约。

## 闭包身份与复制

具体闭包类型由 lambda 源表达式及外围泛型实参共同决定，类型名不能手写。同一具体泛型实例内重复执行同一表达式产生相同类型；不同 lambda 即使拼写相同仍是不同类型。

同类型闭包赋值会复制值捕获，并让 Write 捕获指向源闭包捕获的对象，不向该对象本身赋值。`let copy = closure` 拥有独立捕获值；Write 捕获仍引用原存储。按值捕获一个含 Write 捕获的闭包后，仍允许它修改原先指向的对象。

不可变闭包所有者可以调用其已存储的 Write 权限。Take 整个闭包使源所有者不可用，目标保留 Write 捕获关联。复制闭包、把它放入聚合或从函数返回，都不会延长捕获所指对象的生命周期。返回的闭包可以引用调用者传入的 Write 参数，但必须满足生命周期要求；不能引用被调用函数自己的局部所有者。

## 签名上下文

期望可调用视图可以提供省略的 lambda 参数类型；无上下文时参数类型必须显式。显式返回类型优先，其次使用期望可调用视图的返回类型，否则独立推断各 return 的一致类型。完成闭包类型前检查函数体。表达式体本身也可以产生 lambda，如下例中的 `factory`。

```carven
fn apply(callback: fn(i32) -> i32, value: i32) -> i32 => callback(value);

let offset = 2;
let factor = 3;
let scale = [factor](item: i32) => item * factor;
let factory = [](value: i32) => [value](_: i32) => value;
let seven = factory(7);
println(apply([offset](value) => value + offset, 40), scale(4), seven(0)); // 42 12 7
```

## 可调用视图与生命周期

`fn(...) -> R throw E + F` 表示“可以调用一个具有这些参数和结果的目标”，但不拥有目标的捕获存储，这就是可调用视图。参数访问、参数类型和成功结果要求精确匹配，源的失败集合可以是目标的子集。数组适配递归应用到元素，包括零长度数组。参数或成功结果类型内部的可调用值失败契约仍要求相同。

可调用视图可作为参数、局部值或局部数组元素；不能放入结构体或枚举、返回或被 lambda 捕获。把视图再包进数组也不能绕过这些限制。

带捕获的临时 lambda 只有作为直接实参时才能适配为可调用视图，持续到该调用结束。具名的捕获闭包可在所有者的生命周期足够长时形成局部视图；它借用闭包对象，不复制捕获。借用仍活动时，闭包所有者不能 Take；让所有借用者离开内层作用域后，仍存活的所有者才可继续 Take。无捕获闭包形成视图时不借用闭包存储，创建表达式仍执行一次。通过 Write 视图参数赋入带捕获的调用目标会被拒绝，因为参数不能保证底层存储具有足够长的生命周期。

## 视图复制与失败集合扩展

复制同类型视图会保存当前的调用目标信息，并保留目标对底层存储的生命周期要求。将已有视图适配为失败集合更大的视图时，新视图会借用源视图的存储。重新赋值源视图后，新视图会调用更新后的目标；数组逐元素进行这种适配时也如此。源视图必须保持存活，已被 Take 的视图不能作为借用来源。

```carven
struct E {}
struct F {}

fn first(x: i32) -> i32 throw E => x + 1;

fn second(x: i32) -> i32 throw E => x + 2;

fn example() throw E + F {
    var source: fn(i32) -> i32 throw E = first;
    let copied = source;
    let widened: fn(i32) -> i32 throw E + F = source;

    source = second;

    println(copied(5)?, widened(5)?); // 6 7
}
```

扩展失败集合后的视图会先调用源视图，再适配调用结果。它不拥有源视图，也不延长捕获存储的生命周期。如果直接适配具体可调用值，则以该可调用值作为目标。

## 调用时的快照

具体闭包调用先选中对象，再求值参数。参数求值期间对同一闭包对象重新赋值，会影响本次调用的捕获。视图调用先保存目标信息：重新赋值当前视图变量影响后续调用，修改已选中的闭包对象仍影响本次调用。

扩展失败集合后的视图以源视图对象为目标。因此，在参数求值期间重新赋值源视图，本次调用也会使用新内容。需要独立的捕获快照时，先复制具体闭包，获得独立的闭包值。复制视图只保存目标信息。

## 已知函数目标

用具名函数初始化的不可变局部绑定，在复制和 视图适配后仍保留该函数作为已知目标。通过它的调用使用函数自身的失败契约（包括显式 `throw` 子句），因此失败集合更大的视图类型不会给这次调用增加失败：

```carven
struct E {}

fn exact(value: i32) -> i32 => value + 1;

let step = exact;
let wide: fn(i32) -> i32 throw E = step;
println(step(1), wide(2)); // 2 3
```

两个调用都不需要 `?`。通过参数、`var` 视图或无法确定的目标调用时，使用视图的契约：若写成 `var step: fn(i32) -> i32 throw E = exact;`，`step(1)` 必须加 `?`，否则报告 `CV-EFFECT-UNMARKED`。

## 静态与解释执行

解释器和静态求值支持闭包所有者、值捕获、Write 捕获、可调用视图及视图失败集合扩大。lambda 中实际到达的函数体必须满足静态执行要求，具名源函数调用须为 `const fn`。闭包类型身份还包含外围泛型实参；未知类型的值捕获不能假定可复制。

调用先于实参求值选定闭包对象，函数体中每次使用捕获时读取该对象当前的捕获值或 Write 目标。闭包所有者和可调用视图只能留在本次执行内，不能冻结为常量；调用完成的结果遵循普通常量保留规则。

## 用一份源码维护接口和实现

模块的数据或函数签名变化后，C++ 工程需要让声明、定义和调用者保持一致。Carven 根据模块中已检查的类型和函数生成头文件与实现，交给你的 C++ 工具链编译、链接和优化。

流收集器返回的报告拥有自己的记录，可以用它看这个过程：

```carven
export struct Report {
    records: Vector<String>,
    total: usize,
    duplicates: usize
}
```

C++ 提供方返回的文本视图只在下一次读取前有效。Carven 把需要保留的记录复制成 `String`，去除重复项，再返回完整报告。`import(cpp)` 声明提供方操作，`export(cpp)` 将收集函数暴露给宿主。[完整源码](https://github.com/ryblust/carven/blob/main/examples/stream_collector/workflow.cv) 展示两个方向。

## 接入现有 C++ 工程

`export(cpp)` 函数获得 `carven/api/<规范模块路径>.hpp` 下的自包含 API 头文件。宿主包含它，在对应的 `carven::api` 模块命名空间调用函数。具体 `import(cpp)` 声明还会获得 `carven/providers` 头文件，为签名类型提供别名；提供方声明和实现仍由 C++ 编写。

在编译器仓库根目录运行完整宿主示例：

```sh
./xmakew build
./xmakew build examples
./xmakew run carven-example-stream-collector
```

宿主在收集期间保留流资源，接收含独立字符串的报告。Xmake 组织源码生成、原生编译和链接。手工构建时，`carven compile -o out` 写出生成文件，还需提供所需原生支持源码、头文件路径和库。`compile --stdout` 则用于查看产物。

## 按正确顺序求值和清理

假设聚合的第一个字段已经成功构造，第二个字段却失败了。求值第二个字段时，第一个值必须保持有效；进入失败路径后，它又需要被清理。生成的 C++ 通过临时值、作用域和结果构造保留这些行为。

Carven 在选定路径上从左到右对操作数各求值一次。Read 保留对输入所需的观察，Write 允许修改，Take 转移所有者并使源不可用。具名返回默认复制，`return &&owner` 才转移。C++ 检查原生组件的构造要求，包括中间存储所需的复制或移动。

Carven 类也使用相同模型。字段决定存储和清理，生成的普通函数实现显式接收者；类声明本身不引入继承、虚分派或分配。

## 根据类型依赖组织头文件

有些声明必须看到另一个类型的完整定义。编译器把由这些要求连接的模块组合成接口组件，其他关系使用前置声明。仅函数体需要的依赖留在实现文件中，因此私有函数体修改可以不改变公开头文件。

生成前，分析检查源类型、访问、所有权、失败集合和异步使用。后端根据已检查程序选择表示并构造 C++ 语法。原生重载、模板、布局和机器码优化由 C++ 工具链负责。[架构文章](/zh/internals/compiler-architecture/) 详细解释各阶段的交接。

## 用相同接口连接异步工作

异步调用返回冷操作，也就是 await 或作为子任务启动时才开始的工作。生成的 C++ 用协程实现源异步函数，驱动器在一个线程上运行就绪延续，并处理输入、事件源和定时器。

`when_all` 按输入顺序保留结果，选择和超时操作在子任务关闭后才交付结果。这段等待使借用的数据一直有效，直到工作及提供方清理完成。

`export(cpp) async fn` 在生成 API 中暴露 `AsyncOperation`。原生宿主用自己的上下文和事件源驱动它，并在执行及子任务关闭前保留资源。取消请求本身不能证明原生回调已停止访问状态，见[运行时边界](/zh/internals/runtime-boundary/)。

## 复用分析已经确定的信息

已知访问决定传参和清理，已知结果位置可能允许直接构造。静态参数在运行前选择分支、展开迭代。固定格式结构和编码证明可以提前准备写入，避免反复解析同一格式。

这些选择保留必要的求值、效果和生命周期。同一份已发布语义程序还能生成普通和测试产物，无需重复编译期工作。保留的分析目录可继续交给 `compile`，产物契约见[工具链参考](/zh/reference/toolchain/)。

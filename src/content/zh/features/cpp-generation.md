## 从程序的含义，生成原生实现

Carven 是以 C++ 为目标的编程语言与编译器。源码描述模块、类型、访问、所有权与失败；编译器检查这些关系，再把成立的语义组织成 C++20 程序。

**你的工作集中在程序要做什么，编译器承担让这些意图在 C++ 中成立的组织工作。** 原生编译器继续负责 C++ 类型要求、对象布局、优化和机器码生成。

## 接口与实现，只维护一份来源

采用头文件与实现文件组织 C++ 时，一个小函数也可能分布在两个文件里。例如：

```cpp
// answer.hpp
#pragma once
#include <cstdint>

std::int32_t answer();
```

```cpp
// answer.cpp
#include "answer.hpp"

namespace {
std::int32_t helper() {
    return 42;
}
}

std::int32_t answer() {
    return helper();
}
```

Carven 把同一意图写在一份源文件中：

```carven
export(cpp) fn answer() -> i32 {
    return helper();
}

private fn helper() -> i32 {
    return 42;
}
```

编译器先建立声明身份，再安排定义依赖。helper 可以写在使用处之后；公开入口与私有实现分别进入适当的产物。这里的 C++ 是手写组织方式的示意，生成的公共入口另有 Carven 的模块命名空间。

接口组件根据完整定义依赖形成，需要时使用前置声明。只存在于函数体的依赖保留在实现中。仅调整私有函数体、保持接口及其依赖不变时，生成头文件可保持不变。

**可见性与类型依赖成为组织接口的依据，声明同步和依赖排序由编译器维护。**

## 顺序、存储与清理，共同生成

手写 C++ 时，需要根据表达式的求值规则安排临时变量、分支与作用域。Carven 源码规定所选路径从左到右求值，每个操作数求值一次；生成时把这份顺序与失败出口、借用存活和清理一起安排。

例如，某个聚合的前一项已经构造，后一项可能失败：编译器需要保住先前的值，并在失败路径结束它的生命周期。成功结果有明确目标时，生成直接构造所需的步骤，避免凭空增加默认构造要求。

这也有具体边界：某些原生不可移动组件若必须先保存再转入聚合，目标 C++ 仍可能拒绝构造。直接最终位置构造与跨失败边界的中间保存具有不同要求。

## 已知信息继续服务于运行时

生成阶段继续使用已检查的事实：

| 已知的语义             | 可以据此安排的原生工作                        |
| ---------------------- | --------------------------------------------- |
| 访问与借用关系         | 参数传递、需要保留的存储与清理作用域          |
| 失败集合               | 具体结果载体、传播分支和 callable 适配        |
| 成功结果的目标         | 直接构造与必要的中间存储                      |
| 固定格式片段与整数规格 | 预备文本、整数写入操作与容量界限              |
| 已证明的文本编码       | 为对应格式化路径选择无需重复 UTF-8 扫描的入口 |

**静态信息不仅用于拒绝错误，也用于选择实现。** 每条路径保留必要的求值、副作用、所有权和失败行为，剩余原生优化交给 C++ 工具链。

## 接回现有的 C++ 工程

产物是可检查、可编译、可链接的头文件与实现文件。C++ 消费者包含生成的公共 API 头，并链接对应实现；项目继续选择原生库、编译选项和调试工具。

Carven 不需要为工程提供者重新实现一套对象布局或机器码后端。它在原生构建之前完成语义检查和源码生成，支持运行时头文件随工具链提供。

C++ 也可以使用模块、模板、代码生成工具和库封装来组织这些工作。Carven 的价值是让它们共同消费源语言已经建立的语义事实，减少项目自行同步规则与配套实现的工作。

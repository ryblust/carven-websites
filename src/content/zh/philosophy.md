## 在原生能力之上，建立一致的语义

C++ 提供对象、模板、容器、算法和成熟工具链。Carven 在这些能力之上，让访问、所有权、求值和失败以统一的源语言规则表达，再由编译器安排相应的原生实现。

**表达层次提高，运行时行为仍有具体依据。** 一个语言形式需要说明它允许怎样的程序、提供什么保证，以及需要哪些存储、调用和清理。

## 描述计算，把结果的存储交给编译器

编译期拼接文本时，输入内容、分隔符、拼接顺序，以及何时计算，都由程序员决定。结果有多少字节、如何为这些字节保留静态存储，则可以由编译器根据结果确定。

[编译期教程](/zh/learn/constants/)把两份完整实现放在一起。C++20 的 join 用普通循环构造 string，再由 freeze 模板计算长度、建立 array，并提供 string_view；Carven 使用同样的循环，在 const 初始化完成时把 String 冻结为 str。

更换输入文本时，算法不变，结果长度可以改变。Carven 把构造结果所需的存储安排纳入语言规则，程序员不必为每个结果重新组织这套配套代码。C++ 库也能封装这些工作；Carven 让这种能力直接适用于所支持的常量构造。

## 把需要作出的决定留在源码中

读取、修改与转移所有权，是不同的意图。Carven 用 Read、Write、Take 表达它们，在声明和使用处检查相应权限。推断负责补齐可确定的信息，显式操作负责表达访问、捕获和传播选择。

在 C++ 中，移动后的对象如何继续使用取决于类型与操作的约定。Carven 的 Take 还改变源 owner 的静态可用性，编译器会检查后续使用与恢复。函数调用、闭包和控制流汇合处也遵守这条规则。

对于已知的借用关系，编译器检查底层存储是否保持存活；外部 C++ 指针指向的对象是否有效，仍由提供者与调用者保证。检查范围随编译器实际掌握的信息确定。

## 让组合保留细节

函数与回调组成业务流程时，失败保留各自的类型与载荷。编译器为私有实现推断组合后的失败集合，检查共享接口声明的上界，并从向外传播的集合中移除已完全处理的失败。

模块可以保留各自的失败类型，调用者根据接口声明处理剩余的失败。求值顺序、局部清理与原始失败身份一起保留，恢复策略由业务定义。

[失败契约教程](/zh/learn/failures/)进一步展示了这种分工：价格缺失时是否使用默认值，是程序员的决定；恢复之后还剩哪些失败，是编译器可以推导和检查的事实。C++23 的 expected 与 variant 可以表达相同结果，但错误集合的组合、转换和分支需要由代码或库组织。

这些规则也作用于修改后的程序。删除一个恢复分支后，原有的公开契约可能不再成立；Carven 会据此拒绝实现。规则持续参与检查，示例才不只是一次运行结果的展示。

## 用已知事实减少工作

常量函数可以通过循环和可变局部值构造数据；必需常量上下文决定何时执行、哪些结果能够冻结。编译期测试在生成目标程序前检查这些结果。

动态操作也可以包含已知结构。编译器可以提前准备固定文本、整数格式和容量界限，运行时按这些信息执行。即使结果已知，编译器仍须判断是否可以省略相应求值，并保留所需的副作用和对象生命周期。

静态检查与原生优化各有职责。Carven 确定类型、模式覆盖、求值顺序、所有权和失败契约；简化必须保留必要执行与存储观察。C++ 编译器负责原生优化，包括在证明安全时消除存储。

## 把现有的库接进来

这些语言规则建立在可继续使用的原生生态上。[第三方库示例](/zh/learn/interop/)直接调用 nlohmann/json，取得库提供的对象，再调用它的方法。这个调用无需专门的绑定层；依赖与包含路径继续由原生工程管理。

接入边界也需要写清：Carven 不把原生异常自动变成类型化失败，也不能证明任意外部指针的生命周期。程序员可以在适配层建立需要的契约，再让 Carven 在已知范围内检查和组合它。

## 以等价的手写 C++ 衡量成本

Carven 的成本基线是提供同样求值、所有权、生命周期和检查保证的熟练手写 C++。仅供编译分析使用的信息不必保留为运行时状态；运行时需要保留的状态与操作由程序行为决定。

生成的 C++ 可以直接检查，性能也可以沿用原生工具测量。编译耗时、产物大小、分配和运行时间分别评估，具体收益依赖操作与工作负载。

## 让一份事实贯穿实现

源码中的模块与可见性决定接口组织，语义中的访问和失败决定调用与存储，已知值与结构决定可提前准备的工作。后续编译阶段复用这些检查结果，减少程序员需要重复声明的信息。

**Carven 的目标，是把高阶表达落实为有据可查的原生程序。** C++ 库和工具链提供基础，语言与编译器负责把这些基础组织成一致、可检查的编程体验。
